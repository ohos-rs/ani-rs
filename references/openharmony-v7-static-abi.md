# OpenHarmony 7.0 ArkTS 1.2 static ABI baseline

ani-rs uses the OpenHarmony 7.0 Release source as its API 26 compatibility
baseline. Files from `master`, old feature branches, cached ABC files, and
third-party migration notes do not redefine this contract.

## Pinned source

| Contract | Repository revision | Source |
| --- | --- | --- |
| ANI C ABI | `interface_sdk_c` `5606a8c25984d281d22f4f9f83d6c5111164edca` (`OpenHarmony-v7.0-Release`) | `ani/ani.h` |
| ArkTS runtime and static stdlib | `arkcompiler_runtime_core` `3e147bb76e0b622cc2e4399ef954b030c0639691` (`OpenHarmony-v7.0-Release`) | `static_core/plugins/ets` |

The checked-in `include/ani.h` is byte-for-byte identical to the tagged
`interface_sdk_c` header. Its SHA-256 is
`29975ae6b9c87043e8f7f21394259b216a9cf193369b08191b41fc8f45c64f65`.

The ANI header defines the C function table, opaque handles, status values,
and native entry points. It does not define ArkTS managed class descriptors,
constructors, or inheritance. Those come from the static stdlib used by
es2panda and the matching boot stdlib in the system image.

## Static stdlib contract

| Surface | OpenHarmony 7.0 definition | ANI lookup/signature |
| --- | --- | --- |
| Typed arrays | `std/core/TypedUArrays.ets`, package `std.core` | `std.core.Uint16Array`, `Lstd/core/Uint16Array;` |
| Enum base | `std/core/BaseEnum.ets` | constructor `(value: T, name: string)` |
| Error base | `std/core/Error.ets`, package `std.core` | `std.core.Error` |
| Error constructor | `Error(message?: String, options?: ErrorOptions)` | `C{std.core.String}C{std.core.ErrorOptions}:` |
| Derived errors | `std/core/Errors.ets` | `RangeError` and `TypeError` extend `std.core.Error` |

The release ANI tests construct and throw errors with exactly the class and
constructor signature above. The compiler output is the final check for a
specific application: official ANI guidance requires class descriptors and
method signatures to match the records and functions emitted into the ABC, as
shown by `ark_disasm`.

The 7.0 Release C header still contains `Any_*`, primitive
`FixedArray_New_*`/`GetRegion_*`/`SetRegion_*`, and reference FixedArray APIs.
Later changes on `interface_sdk_c/master` that remove `Any_*` or rename
primitive FixedArray handles to ValueArray are outside the OpenHarmony 7.0
Release ABI and must not be mixed into an API 26 build.

## Compatibility rule

An API 26 application must use a compiler static stdlib and system image built
from the same ABI generation. A system image that exposes
`escompat.Uint16Array`, a one-argument `std.core.BaseEnum` constructor, or an
`escompat.Error` base cannot run ABC generated by the OpenHarmony 7.0 Release
compiler correctly. ani-rs therefore uses only the `std.core` 7.0 descriptors
and reports an ABI mismatch when the matching class is absent; it does not
fall back to the removed `escompat` hierarchy.
